# Settr: Internationalization (i18n) and Terminology

> Status: **Draft v0.4** (question rounds 1–7 incorporated) · Last updated: 2026-09-24
> Library decision → `DECISIONS.md` ADR-008 / ADR-019. References like (Q3.1) or (R2.3) point to decisions in [`USER_QUESTIONS.md`](../USER_QUESTIONS.md). All three question rounds are answered (R3.x = round 3, 2026-09-23).

## 1. Two different "languages"

| Concept | Values | Where it matters |
|---|---|---|
| **UI language** (*Oberflächensprache*) | **Deutsch only in v1** (Q3.1). English can be added later without refactoring, because every string already lives in the message catalog | All app text, number/date formats (`de-DE`) |
| **Card language** (*Kartensprache*) | **`de`, `en`, `ja`, `zh-cn`, `zh-tw`**: Simplified Chinese (Q3.2/Q3.3) and Traditional Chinese (R2.3) are both active, for cards and sealed products. `fr`, `it`, `es`, `pt`, `ko` stay disabled | The printed language of a physical card or product, part of every holding and price series |

**Card-name display** (setting *Kartennamen anzeigen in*):
1. *Sprache der Karte*: the collection shows a Japanese copy in Japanese. This is the default in the collection.
2. *Oberflächensprache*: German names wherever they exist (falling back to the original). This is the default in the catalog.
3. *Originalsprache*: always the print's own language.

The secondary name (another language) appears in muted text on detail pages: "Pikachu-ex · ピカチュウex".

**Derived names** (`nameSource = derived-*`, see `DATA_SOURCES.md` §4) are shown with a small *übersetzt* hint. Examples: the German name of a Japanese-only card, or a Chinese Pokémon name built from open species data (PokéAPI `zh-Hans` for Simplified, `zh-Hant` for Traditional; sources in §4). That way nobody mistakes them for printed text.

## 2. Implementation (Paraglide JS 2)

- **Project:** `src/i18n/project.inlang` with the message file `messages/de.json` (**base and only locale in v1**). `messages/en.json` is added when English is wanted.
- **Compiled output:** typed, tree-shakable functions such as `m.collection_empty_title()` and `m.price_stale_days({ days: 21 })`. A missing parameter is a **type error**.
- **Build:** the Vite plugin compiles the messages on `dev`/`build`, and `pnpm typecheck` runs `pnpm i18n` first. The output `src/i18n/paraglide/` is generated and git-ignored. The inlang message-format plugin is loaded from `node_modules` (path in `project.inlang/settings.json`), not from a CDN, so compiling works offline and in CI. Components import `m` from `@/i18n`.
- **Locale strategy:** v1 has a fixed `de`. Once a second locale exists: `["localStorage", "preferredLanguage", "baseLocale"]`, with switching via `setLocale(locale, { reload: false })` plus a React re-render via a small `LocaleProvider`. (Brave's fingerprinting protection reduces `navigator.languages` to its first entry, R2.9.)
- **Key naming:** `<feature>_<screen|component>_<element>` in snake_case, e.g. `collection_table_col_value`, `session_summary_updated`.
- **Plurals:** Paraglide variants backed by `Intl.PluralRules`, e.g. `"{count} Karte"` / `"{count} Karten"`. Every message with a count has a singular form. It takes `n` (the number, which picks the form) and `count` (the text from `formatCount`); `"{count} von {total} …"` picks by `total`. A zero case matches `n=0` before the plural (`bulk_move_short`).
- **Rich text** (bold, links inside sentences) uses the Paraglide React adapter. No `dangerouslySetInnerHTML`.
- **Zod error messages** use Zod 4's built-in German locale, with Settr-specific messages in the catalogs.
- **Quality gates:**
  - CI fails on hard-coded UI strings (lint rule) and, once `en.json` exists, on keys missing from either catalog.
  - A **pseudo-locale** build (`xx`: +40 % length, accented characters) catches truncation during development.
  - A German copy review is part of M6 (done 2026-09-24: plurals, one term per concept, clearer hints; the conventions are in §5 and §6).

## 3. Formatting and parsing

Every formatting goes through `src/i18n/format.ts`. **Never** call `toFixed` or build strings by hand.

| Helper | DE output (v1) | EN output (later) | Notes |
|---|---|---|---|
| `formatMoney(m)` | `1.234,56 €` | `€1,234.56` | `Intl.NumberFormat(locale, { style: 'currency', currency })`; JPY without decimals |
| `formatDelta(m)` | `+12,30 €` / `−12,30 €` | `+€12.30` / `−€12.30` | `signDisplay: 'exceptZero'`, true minus sign (U+2212) |
| `formatPercent(x)` | `+14,6 %` | `+14.6%` | 1 decimal place. `—` if undefined |
| `formatDate(d)` | `23.09.2026` | `23 Sept 2026` | EN column = future, using `en-GB` (EU-centric) |
| `formatRelative(d)` | `vor 3 Tagen` | `3 days ago` | `Intl.RelativeTimeFormat` |
| `formatCount(n)` | `1.234` | `1,234` | |

**MoneyInput parsing rules** (unit-tested table):

| Input (UI = DE) | Result (minor units) | Rule |
|---|---|---|
| `4,5` / `4,50` / `4,50 €` | 450 | Comma = decimal separator |
| `1.234,56` | 123456 | Dot = thousands separator when a comma follows |
| `1.234` | 123400 | In DE, a dot followed by exactly 3 digits = thousands separator |
| `4.5` / `4.50` | 450 | A dot with 1–2 trailing digits = decimal (a forgiving parse for English-habit typing) |
| `1,234.56` | 123456 | Both present: the last separator is the decimal separator |
| `-3` | error | Prices can't be negative |
| `0` | 0 | Allowed (e.g. a gift) |

A future EN UI would apply the mirrored rules. Ambiguous inputs show the parsed value live under the field ("= 1.234,00 €") so the user sees what will be stored.

**Sorting and collation:** `Intl.Collator(locale, { numeric: true, sensitivity: 'base' })` for names. Card numbers sort by the catalog's numeric `sort` key, never alphabetically.

## 4. Catalog localization

- **Card and set names** come from the catalog per card language (TCGdex provides EN/DE/FR/IT/ES/PT for international sets and JA for Asian sets). Chinese names on M6a:
  - **ZH-TW** from `type-null/PTCG-database` (`data_tc`, MIT; all 176 M6a names), falling back to the TC name of a card with the same Japanese name, then PokéAPI `zh-Hant` species names labeled *übersetzt* (R2.3).
  - **ZH-CN** converted from the official Traditional Chinese names with OpenCC (labeled *übersetzt*, ADR-034); PokéAPI `zh-Hans` species names are the fallback, and hand-curated names win. The SC dataset `duanxr/PTCG-CHS-Datasets` isn't used at all (R2.8).
- **Controlled vocabularies** (rarities, energy types, stages, variants, product types, conditions, price types) are **Settr-owned** IDs with DE/EN labels in `src/i18n`. They are **never** raw upstream strings, which are inconsistent across languages.
- **Japanese and Chinese strings** are always rendered with `lang` attributes (`ja`, `zh-Hant` for ZH-TW, `zh-Hans` for ZH-CN) for correct glyphs, fonts (Noto Sans JP/TC/SC) and screen-reader pronunciation (`DESIGN_SYSTEM.md` §4). Brave's fingerprinting protection may hide named system fonts such as Yu Gothic, so the self-hosted Noto slices must render JA/ZH on their own (ADR-027).
- **Search** normalizes umlauts (`ü`↔`ue`), accents, width variants and kana (`ARCHITECTURE.md` §7), so "Glurak" finds Charizard and "Pikachu" works in any script.

## 5. Tone of voice

- German, informal **"du"** (Q2.4), concise and confident, with collector vocabulary (see the glossary).
- Sentence case for labels and buttons ("Preis eintragen", not "Preis Eintragen").
- Numbers are precise and always carry a unit or currency. Dates are explicit.
- No exclamation marks in system messages, no emoji in UI chrome, no marketing speak inside the app.
- Buttons and links that show something say *anzeigen* (*Abgeschlossene anzeigen*, *Alles anzeigen*), not *zeigen*. Buttons that save and move on use „&“: *Speichern & weiter*, *Anlegen & weiter*.
- Sort options name the key alone (*Nummer*, *Name*, *Seltenheit*), without *Nach*. A setting's options can carry the preposition instead (*Preis veraltet* · *Nach 14 Tagen*).
- Errors say what's wrong, in the third person: *„4,5x“ ist kein gültiger Preis.*, *Die Menge muss zwischen 1 und 999 liegen.* The app never speaks as *ich*.
- After a colon, a full sentence starts with a capital letter (*Nur ein Vorschlag: Gespeichert wird erst, …*).
- **Taglines:** short *"Jede Karte zählt."* (R2.7) under the wordmark in the sidebar and as the PWA description. Long *"Jede Karte. Jedes Set. Jeder Cent."* for README and *Über*.
