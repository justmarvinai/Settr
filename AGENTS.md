## 1. Critical rules (summary; the full list is in `CLAUDE.md`)

1. **Local-first:** no backend and no runtime calls to data APIs. The catalog is static JSON generated by `scripts/catalog`.
2. **Money** is integer minor units. User-data changes need a migration + fixture + round-trip test. Deletes write tombstones. IDs are UUIDv7.
3. **Layering:** `domain/` is pure. Only `db/` touches IndexedDB. Only `catalog/` fetches catalog data.
4. **i18n:** no hard-coded strings. **German only** in v1 (ADR-019), but every string lives in the message catalog.
5. **Design:** tokens only, reduced motion respected, WCAG 2.2 AA, P/L never color-only. Usability beats decoration (Marvin: *"Usability and user experience is always #1"*).
6. **Licensing:** no GPL code (the holo effect is clean-room), no Pokémon logos in branding, self-hosted fonts.
7. **Definition of Done:** `docs/QUALITY.md` §1. **Ask instead of guessing** about product behavior.

## 4. Handoff protocol

### 4.1 Task brief template (lead → agent)

```md
## Task: <short title>  (Milestone M?, Feature IDs: COL-01, …)
**Goal:** <one paragraph, user-visible outcome>
**Owned paths (write):** <globs>
**Read-only context:** <docs sections, files>
**Contracts:** <types/interfaces to implement or consume, with file paths>
**Acceptance criteria:** <bullets, from PRODUCT_SPEC / UX_SPEC>
**Tests required:** <unit/integration/e2e specifics>
**Out of scope:** <explicit non-goals>
**Report back:** use the report template (§4.2)
```

### 4.2 Report template (agent → lead)

```md
## Report: <task title>
**Status:** done | partial | blocked
**Summary:** <what changed and why, 3–6 bullets>
**Files changed:** <list>
**Verification:** <commands run + results, e.g. `pnpm test` ✔ 142 passed>
**Deviations from brief / spec:** <none | list with reasons>
**Open questions:** <for lead/Marvin>
**Follow-ups:** <suggested next tasks>
```

### 4.3 Rules

- **Contracts before parallelism:** shared types live in `src/domain/**` and are merged first.
- **One owner per path per task.** Touching a path you don't own requires lead approval.
- **Never** leave a branch red. If blocked, report `blocked` with the exact error.
- Claims must be verified: "tests pass" means the command was run and its output checked.

## 5. Workflow conventions

- **Branches:** `feat/<milestone>-<topic>`, `fix/<topic>`, `docs/<topic>`, `chore/<topic>`. The current planning branch is `claude/great-edison-uri1z0`, and `main` (created at the start of M1, R3.3) is the default branch; milestone work merges into it.
- **Commits:** Conventional Commits in English, imperative mood (`feat(collection): add quick-add mode`).
- **What never gets committed (ADR-029):** secrets and personal collection data. While the repository is public (it stays public for now, R3.2), also Cardmarket price-guide snapshots (`cm-prices.json`) and the deployment URL.
- **Pull requests:**
  - One per coherent change, and at least one per milestone.
  - The description lists the feature IDs, screenshots (light + dark, mobile + desktop for UI) and the Vercel preview link.
  - It includes the DoD checklist below.
- **Docs in the same PR:** `CHANGELOG.md` (Unreleased), `ROADMAP.md` checkboxes, specs/ADRs when behavior or architecture changes.

### 5.1 PR checklist (copy into every PR)

```md
- [ ] Feature IDs + acceptance criteria met (link)
- [ ] typecheck · lint · format · unit · integration · e2e (affected) all green
- [ ] German strings in the message catalog, no hard-coded text; German layout checked
- [ ] a11y: keyboard, labels, focus, axe clean; reduced motion + reduced transparency respected
- [ ] responsive 375/768/1280/1920, light + dark
- [ ] budgets (size-limit) OK
- [ ] user-data shape unchanged, or migration + fixture + round-trip test added
- [ ] CHANGELOG / ROADMAP / docs updated
- [ ] preview deployment smoke-tested
```

### 5.2 Review checklist (lead / QA)

1. **Correctness:** matches `DATA_MODEL.md` formulas, edge cases (0 cost, unpriced, partial disposals), and the time zone (dates are local calendar dates).
2. **Data safety:** transactions, tombstones, migrations, no data loss paths.
3. **Architecture:** layer rules, no runtime data-API calls, no catalog ID parsing, nothing hard-coded to a single set (ADR-028), and no dependency on APIs that Brave disables by default (ADR-027).
4. **UX fidelity:** flows and microcopy per `UX_SPEC.md`. Speed-of-entry targets are kept.
5. **Design fidelity:** tokens, spacing, typography, motion, and no "default shadcn" leftovers.
6. **Performance:** no unnecessary re-renders (React Compiler friendly), virtualization for long lists, lazy chunks.
7. **Security/privacy:** no new third-party requests, CSP-compatible, untrusted input validated, and nothing committed that ADR-029 rules out.

## 6. When an agent is unsure

1. Check the specs (`docs/`) and ADRs.
2. If the spec is silent or contradictory, **don't invent product behavior**. Add the question to `USER_QUESTIONS.md` (next free ID in the right section), mark the code path with `// TODO(Q<id>)`, and tell the lead.
3. Technical choices inside your owned paths are yours. Document non-obvious ones in the PR, and architectural ones as an ADR proposal.
